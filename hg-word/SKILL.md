# hg-word

让中国英语学习者既能迅速理解选中内容在当前语境里的作用，也能在需要时继续掌握词源、使用边界和可迁移用法。

## 选择模式

根据请求选择一种模式，不混用输出格式；词库同步模式是在完整解词模式上增加落盘与验证流程：

1. **完整解词模式**：用户要求深入解释、掌握一个词，或未指定 Auris/JSON。按“完整解词输出”使用 Markdown。
2. **Auris 当前语境模式**：用户提到 Auris Reading、当前语境、折叠/展开内容、`selected_text`，或明确要求 JSON。只按“当前语境 JSON 契约”输出合法 JSON，不输出 Markdown 或额外文字。
3. **05-word + Auris 词库同步模式**：用户要求把词条添加到 Markdown `05-word`、同步 Auris 对应 JSON，或使用“用 hg-word skill 处理这些单词，添加到我的markdown 05-word文件夹中的词库，不重不漏,注意同步添加到auris的词库对应的json，一个一个重构”这类提示词时，执行“词库落盘与同步工作流”。此处的 JSON 指词库索引，不切换到当前语境 JSON 模式。

如果用户提供句子或段落，始终优先解释该内容在当前上下文中的实际含义；如果没有上下文，才使用最常见义项，并明确这是默认语境。

## 输入

尽可能识别以下字段：

- `selected_text`：用户选中的单词、短语或句子；保持原文形式，不擅自改写。
- `sentence`：选中内容所在的完整句子。
- `paragraph`：相邻段落或上下文，可为空。
- `translation`：已有中文翻译，可为空。

缺少字段时使用用户实际提供的信息，不虚构上下文。完整解词模式下，如只有一个单词，可将它作为 `selected_text`。

## 当前语境分析规则

当前语境的目标不是罗列全部词典知识，而是解释 `selected_text` 在当前句子和段落中具体是什么意思、承担什么作用。

1. 优先结合完整句子和段落定意，不孤立套用词典释义。
2. 说明当前的具体含义、词性或句法作用、修饰/指代/搭配对象，以及它对整句话表达的贡献。
3. 只讲理解当前内容所必需的语法。
4. 遇到固定搭配、熟词生义、隐喻或特殊语气时，简短指出。
5. 已有翻译不自然或不准确时，给出更自然的中文表达。
6. 不在当前语境部分展开词源、构词法、通用搭配列表、作者生平或宏大文化分析。
7. 不武断推测作者心理；用“这里强调……”“产生了……效果”等有文本依据的表述。
8. 中文自然、具体，避免堆砌语法术语。
9. 不重复结论，不写空泛的“增强表达效果”。
10. 上下文不足时明确说明，不得编造。

按选中类型调整重点：

- **单词**：本句词义、词性、搭配对象和语气。
- **短语**：整体含义、内部结构和在句中的成分。
- **句子**：主干、关键从句或非谓语结构、逻辑关系和自然翻译。

## 当前语境 JSON 契约

Auris 当前语境模式严格输出：

```json
{
  "summary": "用于折叠状态的简短说明",
  "detail": "用于展开状态的完整语境解析"
}
```

必须满足：

- `summary` 为 30～55 个汉字，最多 2 句。
- `detail` 为 90～160 个汉字，最多 4 句。
- 结构简单时主动缩短，不为凑字数添加无关内容。
- `selected_text` 必须以原文形式展示一次；避免在 `summary` 和 `detail` 中机械重复。优先在 `detail` 展示，除非折叠说明离开原文就无法成立。
- 输出必须可被 `JSON.parse` 直接解析：使用双引号，正确转义内部引号，不加代码围栏、注释、前后说明或尾随逗号。

## 完整解词质量要求

- 每次解释至少包含 3 个只属于该词的具体信息，例如真实词源、构词结构、典型搭配、语域、常见句型、近义词区别、误用点或当前语境功能。
- 词源或构词不确定时明确写“不确定”或“常见解释是”，不能编造。
- 解释落到可使用的语言知识上，避免可套用于任何词的抽象感悟。
- 金句可以有洞见，但不能替代具体分析。

## 完整解词输出

直接使用 Markdown，并按以下结构输出。

### 1. 标题行

```text
## {Word}  /{音标}/  {当前语境下的中文义}
```

单词标题可规范为小写后首字母大写；短语或句子保持原文形式。

### 2. 当前语境

先执行“当前语境分析规则”，再输出两层内容：

```text
### 当前语境

**折叠摘要**：{符合 summary 要求的内容}

**展开解析**：{符合 detail 要求的内容}
```

有上下文时，两层内容必须解释当前句义和作用；没有上下文时，明确写“默认语境”，使用最常见义项并给一个短例句。这里不输出 JSON 代码块，但内容质量和长度遵循同一份 summary/detail 契约。

### 3. 词源与构词

- **词源/构词**：说明来源，或词根、前缀、后缀组成。
- **原始画面**：用一句话描述最物理、最早期或最核心的画面。
- **核心意象**：提炼成简洁公式，例如“温暖 + 时间 + 保护 = 孕育”。

### 4. 用法边界

- **典型搭配**：给出 3 个常见搭配或句型。
- **近义词区别**：选 1～2 个易混词，说明实际差别。
- **常见误用**：指出一个中文学习者易犯的误用或过度直译。

### 5. 深层解释

用清晰、有洞见的语言串联词源、构词、语境和用法边界。分段清晰，**加粗**关键词，避免空泛哲学化。

### 6. 一语道破

用一句中英双语金句总结最核心、最可迁移的理解：

```text
> "English sentence. 中文金句。"
```

## 全文所有实词覆盖规则

用户说“所有实词都需要”“整篇文章所有实词”或同义要求时，必须处理全文，不得只挑难词、高频词、生词或自认为重要的词。

1. 建立完整词元清单，至少覆盖名词、实义动词、形容词和副词；同时保留有独立意义的固定搭配与短语动词。
2. 屈折形式归入词典词元，例如 `teeth → tooth`、`suggesting → suggest`；派生词或固定短语若具有独立 lookup key 和可迁移意义，则分别收录，不因词形相近而合并遗漏。
3. 冠词、代词、介词、连词、助动词、纯数字等语法项不建实词词条。纯人名或仅作标识的专名登记在覆盖清单中，但默认不写入词库；具有学习价值的国名、族名或普通名词照常收录。
4. 先按规范化 lookup key 审计现有覆盖，再逐词原位重构或新增；不得用“词库中有相近词”代替当前词元或固定表达。
5. 交付前执行 token 级覆盖审计：原文每个 token 都必须归入目标词元、固定表达组成部分、语法功能词、数字或已登记专名之一，`unmatched` 必须为 0。
6. 留下机器可读清单，记录目标总数、原位重构数、新增数、排除项及最终遗漏检查结果。

## 词库落盘与同步工作流

完成前面的工作后进行提交和补充：

1. 确认源词清单、上下文、`05-word` 目录、`0000-index.md` 和 Auris `word-index.json` 的真实路径；若用户要求所有实词，先执行“全文所有实词覆盖规则”；不得只在聊天中输出词条。
2. 按 Auris 实际 `normalizeLookupKey` 规则审计全部目标。相同规范化键只保留一个权威词条；单词、变体和固定短语若规范化键不同，则分别判断，不因表面相近而漏掉。
3. **一个一个重构**：已有词条在原编号文件中重写，缺失词条才使用下一个可用编号新增。每完成一个词，立即核对标题、五段结构、当前语境与来源信息，不做一次性盲目批量改写。
4. 每个文件使用“完整解词输出”的五段结构；有来源句时必须按该句定意。需要追踪来源时增加 `### 来源信息`，至少记录来源段落或材料名。
5. 全部词条完成后更新 `0000-index.md`，再运行 Auris 仓库已有的同步脚本重新生成 `word-index.json`；不要手工拼接 JSON。
6. 完成前核对：Markdown 实际词条、索引行和 JSON entries 数量一致；目标词无遗漏；索引与 JSON 无缺失或多余；规范化 lookup key 无重复、无空值；相关查词测试通过。
7. 若仓库已有未提交改动，只修改本任务明确涉及的文件，不回退、覆盖或整理其他改动。

## 交付前自检

- 是否选对模式，并严格遵守对应输出格式？
- 是否基于句子和段落定意，而不是只给词典义？
- 是否说明了当前含义、句法作用或搭配对象和整句贡献？
- 是否保留 `selected_text` 原文，并在上下文不足时明确说明？
- 是否避免重复、空话、无依据心理推测和无关扩展？
- 若执行词库同步，是否逐词审计并区分“原位重构”和“新增”？
- 若用户要求所有实词，是否覆盖名词、实义动词、形容词、副词和固定表达，并证明 token 级 `unmatched = 0`？
- `05-word`、`0000-index.md`、Auris JSON 的数量与规范化 lookup key 是否最终一致？
