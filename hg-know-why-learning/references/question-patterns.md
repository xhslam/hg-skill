# 知其所以然追问句式

## 六类核心追问

### 1. 澄清
- “你说的 X 具体指什么？能换成一句不用术语的话吗？”
- “这里的输入、输出、约束分别是什么？”
- “这个概念和相邻概念的边界在哪里？”

### 2. 假设
- “你的判断依赖哪个前提？”
- “如果这个前提不成立，会发生什么？”
- “你是不是默认了数据总是干净/网络总是成功/用户总是合法？”

### 3. 证据
- “哪一行代码/哪句话/哪个例子支持这个说法？”
- “有没有反证或例外？”
- “你怎么验证这个理解不是错觉？”

### 4. 机制
- “它为什么会这样工作？”
- “中间发生了哪几个步骤？”
- “如果去掉这一层，系统会在哪里坏掉？”

### 5. 对比
- “它和 X 的相同点/不同点是什么？”
- “为什么这里不用另一个方案？”
- “哪个方案更容易维护？代价是什么？”

### 6. 迁移
- “换成这个新例子，你会怎么用？”
- “如果规模扩大 10 倍，哪里先出问题？”
- “你能自己造一个反例吗？”

## 按场景使用

### 新概念
1. “只看名字，你预测它解决什么问题？”
2. “你以前见过类似东西吗？”
3. “它存在是为了消除什么痛点？”
4. “如果没有它，最笨的方法是什么？”
5. “现在用自己的话定义它。”

### 公式/算法
1. “每个符号分别代表什么？”
2. “这个公式在极端情况下是否合理？”
3. “它从哪里推出来？不能只背结论。”
4. “换一组数字试算，结果符合直觉吗？”
5. “什么条件下不能用？”

### 代码库
1. “这个文件名暗示它负责什么？”
2. “入口在哪里？数据从哪里进来？”
3. “哪一步做校验？哪一步产生副作用？”
4. “异常会被谁处理？”
5. “如果你要改这个功能，最小改动点在哪里？”

### 错题/错误理解
1. “你当时为什么会选这个答案？”
2. “错误发生在概念、计算、条件识别，还是粗心？”
3. “正确答案和你的答案最早在哪一步分叉？”
4. “下次看到什么信号要警惕？”
5. “造一道同类但换皮的题。”

## 禁用问题替代

- 不问：“懂了吗？”
  - 改问：“用你自己的话解释一遍。”
- 不问：“还有问题吗？”
  - 改问：“哪一步最不确定？定义、机制、证据、还是应用？”
- 不问：“要不要我继续讲？”
  - 改问：“你想先做迁移题，还是先补机制？”
